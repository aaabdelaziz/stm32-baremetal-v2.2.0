Overview

This repository contains small, focused bare-metal firmware projects. The examples use direct register access and CMSIS headers instead of HAL application code.

STM32CubeIDE Setup

Import Old Projects From v1.13 Into v2.2.0

File > Import... > General > Existing Projects into Workspace

Import the project folders and the shared chip_headers folder. Use an external workspace folder, not the repository root.

Step 1: File Menu

Open the import wizard from File > Import....

Step 2: Existing Projects Wizard

Select General > Existing Projects into Workspace, then press Next.

Step 3: Choose Root Directory

Use Browse... and select the folder that contains the old project folders.

Step 4: Select Projects

Enable Search for nested projects and Copy projects into workspace, then select the firmware projects and chip_headers.

Step 5: Existing Project Warning

If CubeIDE says projects already exist, use a fresh workspace or uncheck the projects that are already imported.

Step 6: Confirm Project Explorer

After import, Project Explorer should show the firmware projects and chip_headers.

C/C++ Build vs C/C++ General

STM32CubeIDE has two places that look similar. Use C/C++ Build for the real compiler and linker command. Use C/C++ General for the Eclipse editor/indexer view.

This is the typical symptom when stm32f0xx.h is not resolved correctly:

IDE page What it controls Affects build? Use it for
C/C++ Build > MCU/MPU GCC Compiler > Include paths Real compiler -I include folders Yes Fixing missing header errors such as stm32f0xx.h
C/C++ Build > MCU/MPU GCC Compiler > Preprocessor Real compiler -D macros Yes Selecting the correct STM32 device macro
C/C++ General > Paths and Symbols > Includes Eclipse CDT indexer include folders No Autocomplete, navigation, and editor squiggles
C/C++ General > Paths and Symbols > Symbols Eclipse CDT indexer symbols No Helping the editor follow active #ifdef code
When a build fails, fix C/C++ Build first. After the compiler is correct, mirror the same paths and symbols in C/C++ General so the editor also becomes clean.

Build, Run, And Flash

Use this sequence whenever you switch projects or configurations. It prevents CubeIDE from flashing an old ELF or building a different project than the one you selected.

Step 1: Select Active Configuration

Right-click project
Build Configurations
Set Active
Debug or Release

Step 2: Build Selected Project

Right-click project
Build Project

The toolbar hammer can also build, but the selected project and active configuration must be correct.

Step 3: Confirm Clean Console Output

A clean build ends with Build Finished. 0 errors, 0 warnings.

Step 4: Run Or Debug The Project

Right-click project
Run As
STM32 C/C++ Application

If CubeIDE asks for a binary, choose the ELF from the active configuration that you just built.

In the launch configuration, the project and application must match.

Project:           0-LedToggling
C/C++ Application: Release/0-LedToggling.elf
Build Configuration: Select Automatically

Step 5: Fix ST-LINK Before Retrying Flash

If flashing fails with Failed to start GDB server, CubeIDE already found the ELF but could not initialize ST-LINK.

On macOS, approve the ST-LINK accessory prompt, reconnect the board, and retry with a known data USB cable.

If the probe appears but firmware is unknown or old, update ST-LINK firmware using the ST-LINK upgrade utility.

UART Terminal And Analyzer Test

USART2 uses PA2 for TX and PA3 for RX. Default test settings are 9600 baud, 8 data bits, no parity, 1 stop bit, non-inverted 3.3 V logic.

macOS Terminal

/bin/ls /dev/cu.usbmodem*
screen /dev/cu.usbmodem212403 9600

Use the actual serial port returned by your machine.

Logic Analyzer

Analyzer:       Async Serial
Bit rate:       9600
Data bits:      8
Parity:         None
Stop bits:      1
Bit order:      LSB first
Signal:         Non-inverted
Idle level:     High
Sample rate:    1 MS/s minimum, 5-10 MS/s recommended

ASCII A Frame

0x41 = binary 0100 0001

Start  b0 b1 b2 b3 b4 b5 b6 b7  Stop
  0     1  0  0  0  0  0  1  0    1

At 9600 baud, each bit is about 104 us and a full 10-bit UART frame is about 1.04 ms.

Warnings And Fixes

The full history is documented in docs/troubleshooting-and-warnings.md.

Message Meaning Fix
stm32f0xx.h: No such file or directory CMSIS device include path missing. Add chip_headers/CMSIS/Device/ST/STM32F0xx/Include.
Device selection error CMSIS header does not know the exact STM32F0 part. Add STM32F091xC.
-fcyclomatic-complexity rejected Terminal build used a different ARM GCC than CubeIDE expected. Use CubeIDE bundled GNU Tools for STM32 14.3 first in PATH, or disable/remove that generated analysis option.
_close/_read/_write/_lseek warnings Newlib syscall stubs missing in bare-metal project. Add Src/syscalls.c and Src/sysmem.c.
LOAD segment with RWX permissions FLASH load segment was marked readable, writable, and executable. Mark FLASH metadata sections as READONLY in the linker script.
The final verified 4-UartTxRx build produced 4-UartTxRx.elf without the previous syscall or RWX warnings.
